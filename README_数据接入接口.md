# 数据接入接口说明（v3）

本文件说明 v3 演示平台如何接入真实数据流。平台通过统一的"遥测帧"协议
与决策引擎解耦：无论数据来自内置模拟、历史文件、HTTP 网关还是 WebSocket，
最终都归一为同一种帧，再映射为决策场景（scene）交给内核计算。

## 1. 遥测帧协议

```json
{
  "ts": "2026-09-05T10:00:00.000+08:00",
  "t_src_degC": 120.5,
  "m_dot_kg_s": 50.0,
  "medium": "热水/冷凝水",
  "demand": "发电",
  "continuity": "连续",
  "driver": "余热自驱动",
  "dT_degC": 10,
  "hours": 8000,
  "quality": "good"
}
```

### 字段表

| 字段 | 含义 | 单位/取值 | 必填 |
| --- | --- | --- | --- |
| ts | 时间戳 | ISO 8601 | 建议 |
| t_src_degC | 热源温度 | ℃（25~650 标定包络） | 是 |
| m_dot_kg_s | 热源流量 | kg/s | 与 scale_kW 二选一 |
| scale_kW | 规模（替代流量） | kW | 与 m_dot 二选一 |
| medium | 热介质 | 热水/冷凝水｜烟气｜工艺液体 | 否（默认补全） |
| demand | 用能需求 | 发电｜工艺蒸汽｜供暖/热水｜储热调峰｜供冷（制冷）｜干燥/烘干 | 否（默认补全） |
| continuity | 连续性 | 连续｜间歇 | 否 |
| driver | 驱动来源 | 余热自驱动｜外购蒸汽｜外购电力 | 否 |
| dT_degC | 换热端差 | ℃ | 否（默认 10） |
| hours | 年运行小时 | h | 否（默认 8000） |
| quality | 质量标记 | good｜stale｜over_range｜invalid | 由适配层维护 |

`quality` 语义：

- `good`：数据正常；
- `stale`：连接断开/超时未更新（页面黄条提示"数据过期，结果仅参考"）；
- `over_range`：温度超出 25~650℃（页面按能力圈外处理并提示）；
- `invalid`：缺温度或流量/规模（页面不计算并提示）。

## 2. CSV 历史文件模板

```csv
ts,t_src_degC,m_dot_kg_s,medium,demand,continuity,driver,dT_degC,hours
2026-09-05T00:00:00+08:00,120,50,热水/冷凝水,发电,连续,余热自驱动,10,8000
2026-09-05T00:00:01+08:00,122,51,热水/冷凝水,发电,连续,余热自驱动,10,8000
```

- 首行表头固定（顺序不限）；`medium` 之后的列可省略，用回放页默认值补全；
- 按真实时间戳间隔回放（两帧差即等待时长，单帧最长等待 10s）；
- 仓库内置样例：`samples/telemetry_sample.csv`（含发电/供冷/干燥/越界多段）。

## 3. HTTP/JSON 网关接口

网页定时 GET 你提供的地址，要求响应体为"部分帧 JSON"：

```json
{ "t_src_degC": 150.5, "m_dot_kg_s": 40.0 }
```

至少包含 `t_src_degC` 和 `m_dot_kg_s`（或 `scale_kW`），其余字段由网页
用默认值补全；建议完整返回 `medium/demand/continuity/driver`。

- 轮询间隔可在页面配置（200 ms ~ 10 s）；
- 连续 3 次失败自动标 error 并提示，恢复后自动回 live；
- CORS：若网关与网页不同源，需在响应加
  `Access-Control-Allow-Origin: *`（开发/局域网演示）；
- 最小参考实现见 `io-bridge/server.py`。

## 4. WebSocket 推送接口

网页连接 `ws://<host>:<port>/ws`（地址可在页面配置），服务端逐帧推送
与 §1 同构的 JSON 文本消息。断线自动按 1s→5s→15s 退避重连，
重连期间标 stale。适合对接本地采集桥或工厂实时数据平台。

## 5. 与引擎的边界

- 数据接入层只做"传输质量"标记，不做决策；
- 温度越界、需求未知等仍由决策内核的 `validate_scene` 处理
  （25~650℃ 包络、>650℃ 专项设计提示、除湿未单列等）；
- 决策内核（engine.js）为纯函数，与线上 Streamlit 平台同源，
  已通过 Python↔JS 对拍（11 场景 0 差异）。

## 6. 常见问题

**为什么网页不能直接连 OPC UA / Modbus？**
浏览器安全模型不允许网页直连工业协议端口。需要一台本机/局域网采集桥
（参考 `io-bridge/README_采集桥.md`）把读数转成 HTTP/WebSocket。

**HTTP 地址填了但连不上？**
先 `curl <地址>` 确认可返回 JSON；若跨域，检查网关 CORS 头；
若在 `file://` 直接打开页面，部分浏览器限制跨域请求，建议把页面挂到
本地 HTTP 服务（如 `python -m http.server`）再测试。

**数据时间戳与电脑时间不一致？**
页面按"接收时间"计算数据新鲜度，时间戳仅用于 CSV 回放节奏；
现场部署建议网关与前端做 NTP 校时。

**断线后结果还能看吗？**
页面保留最后一帧与最近 60 帧曲线，但会黄条提示"数据过期，结果仅参考"，
避免把过期数据当实时结论。

## 7. 对接真实工厂前的检查清单

- [ ] 现场数据点与帧字段映射表已建立（温度/流量/端差/需求/连续性）；
- [ ] 采集桥与控制器之间使用内网隔离 + 认证（OPC UA 安全策略或 Modbus 网关白名单）；
- [ ] 时间同步（NTP）；
- [ ] 越界与断线策略已在工厂侧评审（本平台会标记但不会自动停机/报警）；
- [ ] 本平台输出为"辅助决策参考"，正式工程应用须以现场实测与完整校核为准。
